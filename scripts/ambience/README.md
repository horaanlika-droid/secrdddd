# Как устроен звук сцен и как его пересобрать

Звук экрана `#/sound` — три слоя: **запись** (земля), **полотно** (медленные
аккорды) и **голос** (мотив поверх полотна). Синтез живёт в `app/js/ambient.js`,
а записи — готовые файлы `app/assets/ambience/*.m4a` (2,53 МБ на всё, CC0 1.0;
происхождение — в `app/assets/ambience/LICENSES.md`).

## Файлы этой папки

| Файл | Зачем |
|---|---|
| `build-ambience.sh` | пересборка всего с нуля: скачать открытые записи → привести к 48 кГц/моно → собрать бесшовные петли → закодировать в `.m4a` → измерить. `npm run ambience-build` |
| `loopify.mjs` | сборка петли: сложение слоёв, нормировка по RMS, кроссфейд «хвост в голову», отчёт о стыке |
| `recipes.json` | рецепты петель по сценам (какие дорожки, уровни, длина кроссфейда, целевой RMS) |
| `measure.mjs` | измерение готовых `.m4a`: длина, кодек, RMS, пик → `files-report.json`. `npm run ambience-measure` |
| `files-report.json` | измерения shipped-файлов; из них берутся `bed.seconds` и `bed.peak` в сценах |
| `loop-report.json` | метрики петель до кодирования (RMS, пик, отклонение стыка) |

Черновики (сырые `.wav`/`.f32`, промежуточные петли) скрипт кладёт в
`test-results/ambience/` — эта папка в `.gitignore`, в репозиторий попадают
только готовые `.m4a`, лицензия и отчёты.

## Что нужно для пересборки

`bash`, `node ≥ 18`, `git`, авторизованный `gh` (или `curl`) и `ffmpeg`.
Если ffmpeg нет, скрипт поставит его из npm (`@ffmpeg-installer/ffmpeg`);
можно указать свой: `FFMPEG=/путь/к/ffmpeg npm run ambience-build`.
Нужна сеть: исходные записи качаются из открытых репозиториев (список — в
шаге 2 скрипта и в `LICENSES.md`).

## После пересборки

1. `npm run ambience-measure` (скрипт делает это сам) — обновит `files-report.json`;
2. обновите `bed.seconds` и `bed.peak` в `AMBIENT_SCENES`, если длина или пик
   петли изменились: из них считается бюджет громкости
   (`bedPeak = bedLevel × peak × 1,2`, худшая сцена — «Дождь», 0,845 после
   мягкого лимитера при потолке 0,92);
3. `npm run ambient-test` — 50 проверок, включая сверку цифр сцен с отчётом;
4. `npm run check` — 162 проверки, включая вес файлов, лицензию и формат;
5. послушайте: `npm run ambient-render -- --scene sea --seconds 20 --rate 32000`
   (WAV ложится в `test-results/audio/`). Чтобы рендер играл настоящую запись,
   а не запасной шум, положите сырые петли в `test-results/ambience/f32/`:

   ```bash
   for f in app/assets/ambience/*.m4a; do
     ffmpeg -v error -y -i "$f" -f f32le -ar 32000 -ac 1 \
       "test-results/ambience/f32/$(basename "$f" .m4a).f32"
   done
   ```

   Частота обязана совпадать с `--rate`. Рендер честно пишет, что звучало:
   «настоящая запись» или «запасной шум».

## Почему так

- **Петля 32–52 с, а не 5 с.** Короткую петлю слышно: мозг ловит период.
  Длинная петля + две копии с разными точками входа (`start(t, offset)`) и
  своим медленным дыханием 25–49 с делают повтор ненаходимым.
- **Моно, а не стерео.** Стерео делает движок (две копии в разные панорамы),
  поэтому файл вдвое легче, а поле — шире.
- **AAC в `.m4a`, а не Ogg/Opus.** Opus легче, но WKWebView в Telegram на
  iPhone его не играет — сцена молча осталась бы на запасном шуме.
- **Нормировка по RMS, а не по пику.** Подложка должна сидеть под музыкой
  ровно во всех сценах; редкие всплески (капли, прибой) остаются, их держит
  мягкий лимитер на мастере.
- **Запасной шум сохранён.** Он звучит с первой секунды, пока запись грузится,
  и остаётся, если сети нет, вебвью старый или декодер ошибся. Музыка не
  должна зависеть от того, доехал ли файл.
